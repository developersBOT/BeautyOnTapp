## Method

1. Session setup: cd to repo root; git fetch origin automation/reports; git checkout -B automation/reports origin/automation/reports. Set DATE = output of TZ=Africa/Johannesburg date +%F. Generate a run_id for the report front-matter.
2. Read automation/config.yaml (brands, guardrails, benchmarks) and this agent's playbook automation/agents/04-analyst-solutions.md. Restate the guardrails this agent routes against: Google Ads = recommend-only always; Meta auto-apply only within the pause gate (>=7d old AND >=R300 spend AND 0 conversions) and <=20% budget/run and NEVER for an adset spending >R500/day (escalate); Shopify auto-apply only for feed/SEO attributes, never price/publish/bulk.
3. Read ALL same-day reports already committed in automation/reports/$DATE/ — for each brand: 01-ppc-audit, 02-seo-audit, 03-merchant-feed. If any of the six files is missing, record it under data_gaps and proceed with what exists — never fabricate the missing channel's findings.
4. Per brand, extract every tagged finding from 01/02/03 with its severity (C/H/M/L), impact (1-5), effort (1-5), owning channel, and cited evidence (source report + row). Normalize all findings for the brand into one flat list.
5. Cluster and de-duplicate across channels by ROOT CAUSE, not by channel: a single cause usually surfaces as 2-3 channel symptoms (e.g. an out-of-stock bestseller appears as a feed disapproval/exclusion in 03, wasted Shopping spend in 01, and lost organic clicks in 02). Collapse those into one backlog item that carries all symptoms and the union of their evidence.
6. Compute blended MER = Shopify revenue / (Google spend + Meta spend) for the period: take spend from report 01, pull Shopify revenue read-only via run-analytics-query (verification, not a new audit). If the Google Ads CSV is absent from inbox, compute Meta-side MER, mark Google spend NOT VERIFIED, and log the gap. Compare MER to the 1.82x floor and 5.0x scaling trigger; compare blended CPA to R167 (BoT) / R300 (Pastry).
7. Score and rank each clustered item: apply the config benchmark gates (MER<1.82x = C cash-destructive; blended/Meta CPA over R167/R300 = H; Meta ROAS<1.5x for 7+ days, frequency>3.0, CPM>R300, CTR<0.8% = channel bleeder signals), then order by impact/effort (impact ÷ effort) with C-severity floated to the top regardless of ratio. Judge trends not snapshots (3 bad days = trend, 1 = noise); reject any input figure built on a pre-Feb 23 2026 baseline.
8. For each item assign an owning channel (meta / shopify / google / seo-organic) and a disposition: auto-appliable within guardrails (meta negatives/exclusions/pause-gate/<=20% budget; shopify feed/SEO attributes) vs needs-human / Google-Ads-recommend-only / escalation (adset >R500/day, price, unpublish, restock).
9. Where a top item's disposition hinges on a current fact, verify read-only before recommending: e.g. confirm an adset's age/spend/conversions via ads_entity_get_report against the pause gate, or a live feed attribute via get-product. Cite the pull; never write to any account.
10. For genuinely hard trade-offs — conflicting recommendations across reports, kill-vs-keep where GA4 data-driven and last-click disagree, or cross-channel budget reallocation under ambiguous MER — convene the beautyontapp-decision-council: five advisers (Contrarian, First-Principles, Expansionist, Outsider, Executor) plus a Chairman, every factual hook sourced or tagged NOT VERIFIED, at least one adviser arguing the decision is wrong, output in VERDICT / WHY / DO THIS NOW / VALIDATE / RISKS. Fold the ruling into the backlog as that item's resolution (Findings) and, when it needs T's sign-off, surface it in full under Recommendations. Do not launder an already-made call through the council.
11. Split the ranked backlog for handoff: keyword-opportunity + negative-keyword/audience/placement items -> agent 05; budget/scaling/kill/reallocation items + council verdicts + escalations -> agent 06. Tag every routed item with brand, severity, impact/effort, disposition, and source citation.
12. Write one report per brand to automation/reports/$DATE/04-analyst-solutions-<brand>.md with the mandated YAML front-matter and section order (Summary <=5 bullets | Findings/backlog | Auto-Applied Changes: none | Recommendations | Handoff). Cite every number to its source report + row; tag anything unverifiable NOT VERIFIED; record every assumption under data_gaps.
13. Commit and push: git add -A; git commit -m "analyst-solutions: <brand> $DATE"; git pull --rebase origin automation/reports; git push origin automation/reports (retry 2s/4s/8s/16s on network error). Distinct per-brand filenames prevent conflicts with the other agents' commits.

## Decision logic

- Cluster by root cause, not by channel: collapse the multi-channel symptoms of a single cause (03 disapproval + 01 wasted Shopping spend + 02 lost organic) into ONE backlog item, and de-duplicate identical findings that 01/02/03 each surfaced independently.
- Rank by impact/effort (impact 1-5 ÷ effort 1-5); severity C — cash-destructive MER<1.82x, or a bleeder over the CPA ceiling — always floats to the top regardless of ratio.
- Benchmark gates (config.yaml is authoritative): MER<1.82x = C, escalate a spend-reduction decision to agent 06/T; MER>=5.0x sustained 14+ days = flag the advertising ceiling as the bottleneck for T (never override unilaterally); blended/Meta CPA over R167 (BoT) or R300 (Pastry) = H; Meta ROAS<1.5x for 7+ days, frequency>3.0, CPM>R300, CTR<0.8% = channel bleeder signals.
- Attribution discipline: never call any single platform's ROAS 'true'; judge Meta prospecting on GA4 data-driven, not last-click; apply haircuts (Meta reported conv x0.65-0.75, Google x0.80-0.90) before comparing channels; Google uses the 'Conversions' column ONLY (never 'All conversions' — 194 phantom actions); Shopify revenue is the MER numerator ground truth.
- Data hygiene: reject any input figure built on a pre-Feb 23 2026 baseline (bot-inflated); prefer trend over snapshot (3 bad days = trend, 1 = noise); Purchase is the only primary conversion event.
- Disposition rule (restated guardrails): Google Ads = recommend-only ALWAYS -> escalate / route as Editor CSV or Script; Meta auto-appliable only within the pause gate (>=7d AND >=R300 AND 0 conv) and <=20% budget/run and NEVER for an adset >R500/day (escalate, don't act); Shopify auto-appliable only for feed/SEO attributes, never price/unpublish/bulk.
- Convene the decision-council only for real trade-offs — conflicting cross-report recommendations, ambiguous kill/scale calls, or cross-channel budget reallocation — with disagreement as the product (at least one adviser argues against) to counter AI-sycophancy; do not use it to rubber-stamp a settled call.
- This agent never acts on accounts: every solution is a recommendation or a routed handoff to agent 05/06, so the Auto-Applied Changes table is always 'none'. When unsure whether something is auto-appliable, escalate rather than route it as auto.

**None — this is a recommend-only agent.** It makes no account changes; every output is a recommendation or a git-committed report.

## Escalate — recommend only, never auto-done

- ALL Google Ads items are recommend-only, always (no API/MCP in this environment): budget/bid changes, campaign pause/launch, Merchant Center disapproval fixes — never claim the account was changed; deliver as a ready-to-upload Google Ads Editor CSV, a step list, or a Google Ads Script, routed to agent 06 (budget/scaling) or agent 05 (negatives CSV) for T to upload. Never fabricate account numbers not present in a report or CSV.
- Any Meta adset spending >R500/day surfaced by report 01 — flag for T, do NOT recommend an auto-action; agent 06 escalates rather than acts (config escalate_if_adset_daily_spend_above_zar: 500).
- MER < 1.82x (cash-destructive): escalate the spend-reduction decision to agent 06 / T — synthesis flags it; the kill/scale call is human-authorized.
- MER >= 5.0x sustained 14+ days: flag the advertising ceiling as the bottleneck for T to decide — never override the ceiling unilaterally.
- Any Shopify solution outside the feed/SEO attribute allow-list (price change, unpublish/delete, bulk status change) — recommend only, needs T; likewise product/inventory calls no guardrail permits (restock an OOS bestseller, discounting).
- Any decision-council verdict of no-go or go-but-only-if that requires T's sign-off before agent 06 acts — carry the VERDICT/WHY/VALIDATE/RISKS into Recommendations for the human decision.
- Any finding whose evidence could not be verified — carry it forward tagged NOT VERIFIED and flag that a human/CSV is needed to confirm before any downstream action.

## Report sections

- Front-matter (YAML): agent: analyst-solutions | brand | date | run_id | data_sources_used (which of the six 01/02/03 files were read + any read-only verification pulls) | data_gaps (missing same-day reports, missing Google Ads CSV, NOT VERIFIED figures, assumptions made).
- Summary (<=5 bullets): blended MER vs the 1.82x floor and 5.0x trigger; blended CPA vs R167 (BoT) / R300 (Pastry); count of clustered root-cause items by severity C/H/M/L; whether the decision-council was convened; and the single highest impact/effort item.
- Findings — the prioritized problem -> root-cause -> solution backlog: one row per de-duplicated root cause, each tagged severity C/H/M/L + impact 1-5 + effort 1-5 and sorted by impact/effort (C floated to top). Each row states the problem, the root cause, the collapsed cross-channel symptoms, the owning channel, the disposition (auto-appliable meta/shopify vs needs-human / Google-Ads-recommend-only / escalation), and a citation to the source report + row; unconfirmed figures tagged NOT VERIFIED. Where the decision-council was convened for a hard trade-off, its ruling is folded into the relevant backlog row as that item's resolution.
- Auto-Applied Changes: the literal word 'none' — synthesis agent makes no account changes (stated explicitly per contract; the mandated table is change | before -> after | revert, here empty).
- Recommendations: prioritized human + Google-Ads actions (Google Ads strictly recommend-only, delivered as Editor CSV / step list / Script), each with owning channel and an expected impact range. Any decision-council trade-off needing sign-off is presented here in full — VERDICT / WHY / DO THIS NOW / VALIDATE / RISKS, with at least one adviser arguing against and every factual hook sourced or tagged NOT VERIFIED — since a no-go / go-but-only-if verdict is a human decision for T.
- Handoff: the explicit split — keyword-opportunity + negative/exclusion items -> agent 05 (keywords-negatives); budget/scaling/kill/reallocation calls + council verdicts + escalations -> agent 06 (revenue-expansion); each item carrying brand, severity, impact/effort, disposition, and source citation.

## Handoff to downstream agents

- -> Agent 05 (keywords-negatives): every backlog item whose solution is keyword expansion or negative-keyword/audience/placement work — carrying the exact wasteful search terms from report 01 and the keyword/content gaps from report 02, each tagged Meta-auto-appliable (negatives/exclusions within guardrails) vs Google-Ads-CSV (recommend-only upload).
- -> Agent 06 (revenue-expansion): every budget/scaling/kill/reallocation call — MER-gated scale triggers (>=5.0x sustained), bleeders to pause with the >=7d / >=R300 / 0-conv gate already pre-checked from report 01, cross-channel budget shifts (<=20% per run, ~32/68 Google:Meta frame), plus every >R500/day adset escalation and every decision-council go / no-go / go-but-only-if verdict for final authorization.
- Both downstream agents inherit the ranked severity + impact/effort so they action the highest-leverage items first; every routed item cites its source report + row and names the brand (BoT vs Pastry).
- Anything neither agent 05 nor 06 can action within guardrails (price change, restock, unpublish, ceiling override, discounting) is escalated to T in the Recommendations section and NOT handed to a downstream agent.
